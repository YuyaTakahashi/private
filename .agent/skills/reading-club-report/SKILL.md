# UX DAYS TOKYO 読書会レポート生成スキル

## 1. 概要

UX DAYS TOKYO主催の読書会で扱った書籍のnote.com向けレポートを3ステップで生成する。

**生成フロー:**
1. 書籍内容サマリーの作成（スライドファイル・文字起こしを参照）
2. 骨子インタビュー（骨子.mdのフォーマットに沿って質問を投げる）
3. レポート下書きの生成（`report_draft_v2.md`のフォーマットで肉付け）

**参考ディレクトリ:** `/Users/takahashi_yuya/workspace/private/読書会・勉強会/12歳から知っておきたいAI/`

## 2. ベースパスと書籍フォルダの特定

```
BASE_DIR=/Users/takahashi_yuya/workspace/private/読書会・勉強会/
```

## 3. Step 1: 書籍内容サマリーの作成

### 読み込む素材（優先順位順）

1. **スライドファイル**（`.pptx` / `_スライド内容.md` / 日付.md）
   - `{書籍フォルダ}/*.md` の中でスライド・資料と判断できるもの
   - `.pptx` は直接読めないため `_スライド内容.md` が存在すればそちらを使う
2. **文字起こし**（`*文字起こし*.txt` / `*文字起こし*.md` / `読書会文字起こし.md`）
3. **要約ファイル**（`*要約.md` / `*サマリー*.md`）

### 既存サマリーの確認

`{書籍フォルダ}/書籍内容サマリー.md` が既に存在する場合:
- 内容を読み込み、ユーザーに「既存のサマリーを使いますか？更新しますか？」と確認する
- 「使う」場合はStep 2へ進む

### サマリーの構成

以下の構成で `{書籍フォルダ}/書籍内容サマリー.md` を生成・更新する。

```markdown
# 書籍内容サマリー：{書籍タイトル}

## 全体テーマ
{書籍が伝えたいこと・中心的な主張を2〜3文で}

## 章ごとの要点
{章・パートごとに見出しを立て、各パートの主要な主張・事例・データをまとめる}

## 読書会での議論・発言
{文字起こしがある場合、印象的な発言・問い・気づきをピックアップする}

## キーワード
{書籍に登場する重要な概念・用語のリスト}
```

## 4. Step 2: 骨子インタビュー

書籍内容サマリーを踏まえて、以下の骨子フォーマットを埋めるために**一問ずつ**質問を投げる。
全部まとめて聞かない。回答をもらったら次の質問に進む。

### 骨子フォーマット（参照: `骨子.md`）

```markdown
## 言いたいことを一言で
## 読者が学べること（1〜3項目）
## 結（結論を述べる）
## 起（問題提起）
## 承（伝えたいことの導入）
## 転（伝えたいことの具体的な説明）
## 結（読者がやってみようと思えること）
```

### 質問の進め方

**Q1（一番伝えたいこと）:**
> 読書会を終えて、一言で伝えるとしたら何ですか？（例: 「AIを大きな社会課題解決に使おうと思えた」）

**Q2（読者が学べること）:**
> この記事を読んだ人に、どんな気づきを持って帰ってほしいですか？（1〜3つで）

**Q3（起: 問題提起）:**
> 読者が「あるある」と感じる、今の状況や悩みは何ですか？

**Q4（承: 導入）:**
> 書籍のどんな内容・事実が、問題を解くヒントになりましたか？

**Q5（転: 具体的な説明）:**
> 自分や読者の仕事・生活に置き換えると、どう変わりますか？

**Q6（結: 行動提案）:**
> 読んだ人に「明日からやってみよう」と思ってほしいことは何ですか？

全問の回答が集まったら、骨子を `{書籍フォルダ}/骨子.md` に保存してユーザーに確認を求める。
OKをもらったらStep 3へ進む。

## 5. Step 3: レポート下書きの生成

骨子とサマリーを組み合わせて、以下のフォーマットでレポート下書きを生成する。

### レポートフォーマット（参照: `report_draft_v2.md`）

```markdown

こんにちは。UX DAYS TOKYO スタッフの高橋です。UX DAYS TOKYO主催の毎月恒例のUX読書会、今回は**『{書籍タイトル}』**を取り上げました。

今回の読書会で、{印象的な問い・出来事}がありました。

**「{読者が共感できる問いや発言}」**

{この問いや体験から感じた気づきを1〜2文で}

## {骨子「結（言いたいことを一言で）」に対応する見出し}

{冒頭に結論を述べる。「言いたいことを一言で」を展開し、この記事の主張を最初に伝える。読者が「何を学べるか」を冒頭で示す。}

## {骨子「起」に対応する見出し}

{骨子「起」の内容を肉付けした段落。読者の日常に引きつける。}

## {骨子「承」に対応する見出し}

{書籍の内容・歴史・事実をもとにした解説。サマリーの内容を活かす。}

{サブセクション（### ）で具体的な領域・事例を展開する。}

## {骨子「転」に対応する見出し}

{自分の仕事・業界に置き換えた気づき。「転」の内容を具体化する。}

## {骨子「結（行動提案）」に対応する見出し}

{読者が「明日からやってみよう」と思えるメッセージ。}

## 「気付けない」に「気づく」読書会の魅力

UX DAYS TOKYOの読書会は、単に本を読むだけではありません。問いを投げられ、多様なバックグラウンドを持つ参加者と議論することで、自分一人では気づけなかった「思考の偏り」に気づくことができるのが最大の魅力です。

{今回の読書会で得た全体的な学びを1〜2段落で締める。}
```

### 保存先

`{書籍フォルダ}/report_draft.md` に保存する。
同名ファイルが既に存在する場合は `report_draft_v2.md`（またはv3, v4...）として保存する。

## 6. 文体ルール

- **です・ます調**を使う
- 「〜していませんか？」「〜ではないでしょうか？」のような読者に問いかける表現は使わない。自分の現場や経験の中で起きていることとして書く
- 書籍の内容は自分の仕事・業界に置き換えて説明する
- 「重要な」「極めて」「計り知れない」を避け、具体的な事実に置き換える
- 「浮き彫りにしており」「今後の展開が注目されます」「〜ではないでしょうか」（文末）を使わない
- カタカナ語の連続使用（3語以上）を避け、和語で言い換える
- 「〜することができます」→「〜できます」に短縮
- 「〜とは何か。」「では、〜か。」のような体言止めに近いセクション冒頭の問いかけを使わず、文として書く
- 全角ダッシュ（——）は使わず、カッコや読点に置き換える
- 太字は核心メッセージ・気づきの強調に使う（段落に1〜2箇所まで）
