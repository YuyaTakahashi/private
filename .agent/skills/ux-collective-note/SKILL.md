# UX Collective Note Article Skill

## 1. 概要

UX collective勉強会の情報収集・学習ノート生成（`ux-collective-study-group`スキル）が完了した後に呼び出す。
日付フォルダ内に蓄積された情報と、ユーザーが追記した振り返りをもとに、note.com向け記事を生成する。

**前提:** 日付フォルダ内に `article{N}_{MMDD}.md`（学習ノート）または `memo*.md`/`transcript.md` が存在すること。

---

## 2. 実行ステップ

### Step 1: 日付フォルダの特定

引数で日付フォルダ（例: `0408`）が指定された場合はそれを使用する。
指定がない場合は、以下の方法で特定する。

- `/Users/takahashi_yuya/workspace/private/読書会・勉強会/UX collective勉強会/` の最新フォルダ（MMDD形式）を確認
- 複数の候補がある場合はユーザーに確認する

### Step 2: フォルダ内の全ファイルを読む

以下の優先順位で情報を収集する。

1. **ユーザーの振り返り**（最優先）
   - `article{N}_{MMDD}.md` の「自分の学び」セクションに記入があれば、それを核心に据える
   - `memo*.md` にユーザーが追記したメモがあれば参照する

2. **議論の詳細**
   - `transcript.md` / `discussion_notes_*.md` → 参加者の発言・気づき

3. **記事情報**
   - `article-summary*.md` → 記事の要約
   - `urls.md` / `info.md` → 記事タイトル・URL
   - `gemini_memo.md` → Geminiメモ

4. **スプレッドシートで記事情報を補完**（URLが不明な場合）
   ```
   https://docs.google.com/spreadsheets/d/1aE-9DbB2R11BuEr5pPI7wOk6zzg83Nvldb5OE-70gy4/edit?gid=0#gid=0
   ```

### Step 3: 記事タイプの確認

ユーザーが指定しない場合はタイプAを提案し、確認してから生成する。

| タイプ | 説明 | ファイル名 |
|--------|------|-----------|
| **タイプA**（記事別） | 1記事 = 1ファイル。記事ごとに深掘り | `note_article{N}_{MMDD}.md` |
| **タイプB**（レポート） | 2記事をまとめて1ファイル | `report_{YYYYMMDD}.md` |

### Step 4: note記事を生成・保存

- 既存ファイルがある場合は上書きせず、ユーザーに確認する
- 確認後、上書き or 別名（`_v2`付き）で保存するかを選択させる

## 5. 文体ルール

- **です・ます調**を使う（学習ノートのメモ形式とは異なる）
- **読者への問いかけ**を冒頭〜中盤に入れる（「〜していないでしょうか？」「〜だとすれば？」）
- **現場翻訳**：記事の概念を自分の職場・業務の言葉に置き換えて説明する
- **振り返りの優先**：ユーザーが「自分の学び」に書いた内容を、本文中の個人の気づきとして積極的に使う
- **太字**：核心メッセージ・気づきの強調に使う（段落に1〜2箇所まで）
- カタカナ語の連続使用（3語以上）を避け、和語で言い換える
- 「重要な」「極めて」「浮き彫りにしており」「〜ではないでしょうか」（文末）は使わない
- 「〜することができます」→「〜できます」に短縮
- 全角ダッシュ（——）は使わずカッコや読点に置き換える
