# create-ai-context スキル

指定フォルダ（または現在のディレクトリ）のプロジェクトを探索し、`AI_CONTEXT.md` を生成する。
既存のファイルがある場合は内容を読んだうえで上書き更新する。

## 引数

```
/create-ai-context [フォルダパス]
```

- フォルダパスを省略した場合はカレントディレクトリを対象にする
- 相対パス・絶対パスどちらでも可

## 手順

1. 対象ディレクトリを決定する（引数があればそのパス、なければ `pwd`）
2. プロジェクト構造を把握する
   - ディレクトリ構成（`ls` で1〜2階層）
   - `package.json` / `Cargo.toml` / `.clasp.json` など設定ファイルの有無
   - `README.md` がある場合は読む
3. 主要ファイルの役割を把握する（エントリーポイント・設定・主要モジュール）
4. 既存の `AI_CONTEXT.md` があれば読み、差分更新で済む箇所を確認する
5. 以下のテンプレートで対象ディレクトリ直下に `AI_CONTEXT.md` を生成・上書きする

## 出力テンプレート

```markdown
# AI Context Map: <プロジェクト名>

## Project Overview
<プロジェクトの目的・使われ方を2〜3文で>

## Key Directories & Files
- `<パス>`: <役割>
- `<パス>`: <役割>
  （実際に存在するファイル・ディレクトリのみ列挙する）

## Core Logic Flow
1. **<ステップ名>**: <処理内容>
2. **<ステップ名>**: <処理内容>
   （ユーザーリクエストからレスポンスまでの主要経路を書く）

## Critical Constraints & Tips
- **<制約名>**: <内容>
  （デプロイ方法・環境差異・注意すべきパターンなど）

## Common Tasks for AI
- <AIに頼まれやすい改修・調査のパターンを箇条書き>
```

## 品質基準

- 実際に読んだファイル・確認したパスのみ記載する（推測で書かない）
- 各セクションは「AIが次のタスクを始めるときに必要な前提知識」に絞る
- 1000トークン以内に収める（長くなるほど毎回のコンテキスト消費が増える）
- 生成後、ファイルパスをユーザーに報告する
