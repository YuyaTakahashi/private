# シミュレーションモデルによるUXリサーチの再構築（2/18勉強会メモ2）

## 1. 参照記事と概要
**記事：** [Using simulation models in UX research](https://uxdesign.cc/using-simulation-models-in-ux-research-ba9f4cdcf32c)

### 【記事の要約】
現代のUXリサーチは、心理学や民族学から手法（アンケートやインタビュー）を借りてきたものの、その「設計図（理論）」を置き去りにしてしまったために形骸化している。これに対し、コンピュータ上の仮想世界でユーザー（エージェント）を動かす「シミュレーションモデリング」は、従来の手法の限界を打ち破る強力な武器になる。

*   **「創発」の再現：** 鳥の群れのように、個々が単純なルール（隣にぶつからない等）で動くことで生じる、複雑で予測不可能な全体パターンを観察する。
*   **社会科学のツール：** エージェントベースモデリング（ABM）など、個人の行動が社会全体にどう影響するかをシミュレートする手法をUXに適用する。

### 【ABM（エージェントベースモデリング）の4ステップ】
1.  **エージェントの作成：** 属性や個性の異なる数千〜数万の仮想ユーザーを用意する。
2.  **行動ルールの付与：** 「〜ならクリックする」といったシンプルな行動ルールを設定する。
3.  **インタラクションの実行：** コンピュータ上でエージェント同士やシステムとのやり取りをシミュレートする。
4.  **創発パターンの観察：** システム全体に現れる、予想外のパターンや結果を分析する。

## 2. シミュレーションモデルが答える「5つの問い」
リサーチの限界（バイアスやコスト）を補完するため、以下のような戦略的な問いに答えを出すことができる。

1.  **仮説のリアリティチェック：** 「今の仮説は、実際のシステムデータからどれくらい乖離しているか？」
2.  **自己申告データの検証：** 「アンケートやインタビューの結果（ユーザーの言葉）は、実態と矛盾していないか？」
3.  **スケーリングの影響（転換点）：** 「個々の決定が積み重なったとき、システム全体でいつ・どこでボトルネックや離脱の急増が起きるか？」
4.  **戦略的優先順位：** 「5つの料金プランのうち、実際のコストをかけてABテストをやる価値があるのはどれか？」
5.  **データ欠乏（コールドスタート）：** 「まだ実際のデータがない立ち上げ初期に、どうすれば情報に基づいた意思決定ができるか？」

## 3. 勉強会での議論と気づき

### 参加者の発言まとめ

*   **高橋祐哉さん（私）**
    *   **「点（個人）」から「面（全体）」へ**：現場で1ユーザーの1業務をプロトタイプ（ロープレ）した時は上手くいったが、複数の人が同時に動き出すと問題が起きるという実体験があり、そこに「創発」の概念がリンクした。
    *   **デジタルツインとの類似性**：このモデルは「デジタルツイン」の概念に近いと感じた。テスト（検証）にこの発想を持ち込める点は非常に新鮮で勉強になった。
    *   **既存知識との接続**：エージェントの行動ルールを設定するには、行動科学、心理学、社会学などの知見が不可欠。これまで学んできた内容がまさにここで活きるのだと実感した。
    *   **AIとの境界線**：あくまで簡易的なシミュレーションであり、こそばさんの言う「補助」という概念に非常に納得した。グレッグ・バーンスタイン氏（記事内の言及等）が言うように「AIは人間ではない」ことを念頭に置き、バイアスなどの人間の制約を取り除く手段として付き合っていきたい。
    *   **強みへの転換**：こうした高度な検証手法を実際の成果に繋げることができれば、PdMとしての大きな強みになると感じ、この知見を得られた価値は大きい。
*   **あかねさん（Participant 2）**
    *   **バイアスの検証**：自分自身のバイアス（売れないと思っていたものが売れる等）や、ユーザーの自己申告バイアス（アンケートと実態の乖離）を検証する手段として心強い。
    *   **AIペルソナとの接続**：前回のAIペルソナの話から、リサーチの進化の解像度が上がった。
*   **こそばさん（Participant 5）**
    *   **補助ツールとしての位置付け**：モデルの結果を「絶対」とするのではなく、自分の考えを裏付けたり、新しい視点を発見したりするための「補助」として付き合っていくべき。
*   **大本さん（Participant 1）**
    *   **バイアス防止への期待**：人間の主観やバイアスを防ぐ手法として有効。
    *   **今後の課題**：具体的にどのような手順で実装・運用するのか、まだイメージが追いついていないため深掘りが必要。

### 全体の気づき
*   **「魔法の杖」ではない**：全員が共通して「結果を絶対視せず、自分の仮説の正しさを検証（または間違いを特定）するための武器」として捉えていた。
*   **実装レイヤーの課題**：PdMとして、どのようなツールや手順でこのシミュレーションを実務に組み込むべきか、具体的な手法への関心が高い。
