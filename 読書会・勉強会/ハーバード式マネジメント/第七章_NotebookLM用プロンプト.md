# 第七章「人事を固める」NotebookLM 音声・動画解説用プロンプト

> 使い方：NotebookLM に新しいノートブックを作り、**ソースとして `まとめ/第七章_まとめ.md`** を追加する（必要なら `読書ノート.md` の第七章の項も足す）。
> その後、Audio Overview / Video Overview の「カスタマイズ」欄に下のプロンプトを貼り付ける。
> 2人の対話形式（標準のホスト2人）を前提にしている。

## 貼り付け用（簡潔版）

```
マイケル・ワトキンズ『最初の90日』第七章「人事を固める」を、マネジメント初学者に向けて2人の対話で噛み砕いて解説してください。聞き手役は、評価の数値化や厳しい人事判断にまだ馴染みのない素朴な質問者として「それってつまりどういうこと？」と何度も掘り下げ、解説役が日常の言葉でかみ砕いてください。専門用語は必ず言い換えること。

特に次の5点を、つまずきやすい論点として丁寧に扱ってください。
(1) なぜ人事が最初の90日で最も重要な決断なのか（飛行機を飛ばしながら修理する、という比喩を使って）。
(2) 部下を6項目（能力・判断力・エネルギー・集中力・対人関係・誠実さ）で評価し、100点を配分する意味。これは精密な測定ではなく「自分が部下の何を重視しているかを言語化する」ための道具だと強調する。
(3) 評価の配点に、リーダー自身の「人の弱点を直せるか／直せないか」という人間観が表れるという考え。自分が直せる弱点なら採用してよく、直せない弱点は採用時に弾く、という戦略として説明する。
(4) 「残さない判断（退出・配置転換）」は切り捨てではなく、合わない場所に置き続けること自体が本人にも不幸だから合う場所を探す判断でもある、という冷徹さと誠実さのセット。
(5) プッシュ（報奨・ルールなど外から押す動機づけ）とプル（ビジョン・仲間意識など内から引き寄せる動機づけ）の違いと使い分け。

事例のリアム・ジェフィン（偏った人事考課を鵜呑みにせず自分の基準で再評価した話）を具体例として織り込んでください。抽象論の羅列は避け、聞き終えたあとに「明日から自分のチームで何を観察すればいいか」が分かる状態をゴールにしてください。日本語、10〜15分程度。
```

## 詳細版（じっくり指定したいとき）

```
■ 題材
マイケル・ワトキンズ『最初の90日』第七章「人事を固める」。提供したソース（章のまとめ）だけを根拠にしてください。

■ 対象リスナー
プロダクトマネジャー／エンジニアリング寄りのマネジメント初学者。人を「残す／残さない」の最終判断をこれまで上司に任せてきて、自分では考えたことがない人。評価の数値化や厳しい人事判断に心理的な抵抗がある。

■ 形式
2人の対話。
・解説役：内容を構造立てて説明するが、専門用語は必ず日常語に言い換える。
・聞き手役：初学者の代弁者。「それって結局どういうこと？」「冷たくない？」「数値化って意味あるの？」と素朴な疑問・抵抗を率直にぶつけ、納得するまで掘り下げる。

■ 噛み砕いてほしい論点（つまずきやすい順）
1. 人事は90日で最も重要な決断。なぜか＝優れた人材で固めれば高い成果、誤れば長く祟る。「人事と組織設計は同時に進める＝飛行機を飛ばしながら修理する」比喩を必ず使う。
2. 引き継いだ人事考課を鵜呑みにしない。リアムの例（優秀と無能しかなく中間がいない考課表＝前任者のバイアスのサイン）で具体化。
3. 評価6項目＋100点の重みづけ。数値は測定でなく「自分の優先順位を炙り出す道具」。今すぐ正確に配点する必要はなく、まず「自分は部下の何を一番見ているか」を3つ挙げるところからでよい、と安心させる。
4. 配点に自分の人間観が出る＝「直せる弱点／直せない弱点」の戦略。自分の強みでカバーできる軸は配点を下げてよく、カバーできない軸を上げる。
5. 「残さない判断」＝切り捨てではない。解雇以外の道（役割変更・他部署異動・合う場を探す）を先に探る。冷徹さと誠実さはセット。合わない場所に置き続けることは本人にも不幸。
6. プッシュ（外から押す＝報奨・ルール・締切）とプル（内から引き寄せる＝ビジョン・仲間意識）。磁石の比喩。相手のタイプで組み合わせを変える。報奨制度は目標と矛盾させない（チームプレーが欲しいのに個人プレーを報いる制度はNG）。
7. 意思決定プロセスの使い分け（独断／リーダーシップ方式／コンセンサス方式／全会一致）。「最後は私が決める」と正直に言う方が、見せかけの合意より良い、という点を強調。

■ トーン
カジュアルで聞きやすいが、中身は薄めない。励ましすぎず、しかし初学者の抵抗感（「人を切る判断なんて怖い」）に共感してから解きほぐす。

■ 避けること
原書の細かい数字の暗記、抽象的な訓示の羅列、結論の出ない一般論。

■ ゴール
聞き終えたあと、リスナーが「明日から自分のチームで、まず何を観察し、どんな問いを立てればいいか」を1つでも持ち帰れる状態。

■ 仕様
日本語。12〜18分程度。
```

## 補足メモ

- NotebookLM のカスタマイズ欄は文字数制限があるため、入りきらない場合は**簡潔版**を使う。
- 他の章でも使い回せる。題材タイトルと「噛み砕いてほしい論点」を、その章の `まとめ/第◯章_まとめ.md` の見出しに差し替えればよい。
- 「自社の実例（エンジニア部門・リソース配分）に絡めたい」ときは、簡潔版の末尾に一文足す：「リスナーが直面している『エンジニアリソースの配分を誰がどう裁定するか』という課題に引きつけて、第七章の考え方をどう当てられるかにも触れてください。」
